# subview 输入协议

> 版本：v1（随 `subview 0.1.x` 提供）
> 状态：稳定。向后兼容的扩展只会新增事件类型或字段。

subview 从标准输入读取 UTF-8 字幕流，把它排版到屏幕上。本文档是 **producer 作者**的接口
约定：只要按这里的格式写 stdout，任何程序都能驱动 subview。

## 1. 通用约定

- 输入编码为 UTF-8。非法字节序列替换为 U+FFFD，不会导致 subview 退出。
- 输入按 **字节** 解析，因此多字节字符被拆在两次 `read` 之间也没关系。
- 单行上限 64 KiB；超长行只保留尾部 32 KiB，并向 stderr 打印一次警告。
- 显示模式下会剥除文本中的 C0/C1 控制字符（`\t` 除外），防止终端转义注入。
  作为纯文本过滤器使用时（`--raw` 且 stdout 非终端），内容原样透传。
- 事件分为三类：

| 事件 | 语义 | 丢失影响 |
|---|---|---|
| `partial` | 当前未定稿内容，覆盖上一条 partial | 可丢：渲染跟不上时只保留最新一条 |
| `final` | 定稿字幕，追加进历史 | 不可丢：subview 会全部接收 |
| `clear` | 清空字幕区 | 可丢 |

## 2. `plain` 格式（默认）

借用终端自身的行语义，不发明新符号：

| 字节 | 含义 |
|---|---|
| `\n` | 提交：此前累积的字节成为一条 `final` |
| `\r` | 覆盖：此前累积的字节成为一条 `partial`，不提交 |
| 连续空行（立即 `\n`） | `clear` |
| `\r` 后紧跟 `\n` | 一次行结束（CRLF），内容作为 `final` |
| 其余字节 | 累积到当前行缓冲区 |

### 2.1 状态机

```
            其他字节
   ┌──────────────────────┐
   │                      ▼
 [行缓冲] ──\r──► partial（可替换）
   │
   ├──\n──► final（追加历史）
   │
   └──\n（缓冲为空）──► clear
```

- `\r` 时缓冲区内容整体作为 partial 发出并清空缓冲；下次 `\r` 会替换它。
- `\n` 时缓冲区内容作为 final；若缓冲为空则发出 clear。
- CRLF：`\r` 已经发出 partial，紧随的 `\n` 把该 partial 转成 final。
- EOF 时若缓冲区还有内容，作为 final 提交；若只剩未提交的 partial，也作为 final 提交。

### 2.2 示例

| 输入字节 | 事件序列 |
|---|---|
| `你好\n` | `final("你好")` |
| `世界\r` | `partial("世界")` |
| `你好\r\n` | `partial("你好")`, `final("你好")` |
| `你好\r世界\n` | `partial("你好")`, `final("世界")` |
| `\n` | `clear` |
| `未结束`（EOF） | `final("未结束")` |

### 2.3 为什么要借用 `\r` / `\n`

这正是 curl、apt、wget 进度条的惯例：`\r` 擦除重写、`\n` 落定。好处是：

- `echo 你好 | subview` 直接可用，不需要适配器
- 任何逐行输出的老程序天然兼容
- 实时识别"中间结果 / 最终结果"有现成语义，不需要发明新格式

## 3. `jsonl` 格式

每行一个 JSON 对象（UTF-8、行尾可带 `\r`）。空行忽略。

### 3.1 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event` | string | 是 | `partial` / `final` / `clear` |
| `text` | string | partial、final 必填 | 字幕文本 |
| `speaker` | string | 否 | 说话人标签，显示为 `[X] ` 前缀 |
| `t` | number | 否 | 秒级时间戳，仅用于调试；subview 不据此调度显示时机 |
| `lang` | string | 否 | 语言标记，当前忽略 |

未知字段忽略；未知 `event` 忽略并警告（同类警告限流为每 5 秒最多一条）。
非法 JSON 行忽略并警告。

### 3.2 示例

```json
{"event":"partial","text":"欢迎"}
{"event":"partial","text":"欢迎收听"}
{"event":"final","text":"欢迎收听本期节目","speaker":"A"}
{"event":"clear"}
```

`text` 为空字符串时忽略（清屏请用 `clear`）。

## 4. 给 producer 的建议

- **实时流**：先发 `partial` 刷新，识别定稿后再发 `final`；不要在 `final` 之前清屏。
- **不要阻塞在显示上**：subview 对 partial 有丢帧策略，producer 可以持续快速输出。
- **不要输出 ANSI 颜色**：控制器由 subview 统一负责；带颜色的输入会被当作普通文本
  （控制字符在显示模式下被剥除）。
- **背压**：subview 始终读取 stdin；partial 在渲染瓶颈时被合并，final 不会丢。
- **退出**：关闭 stdout（EOF 或退出）即可，subview 会在显示完最后状态后正常退出。

## 5. 版本化

当前协议无版本号前缀。向后兼容的扩展（新事件类型、新字段）不会破坏已有 producer；
不兼容的变更会以新 `--format` 值或主版本号发布。
